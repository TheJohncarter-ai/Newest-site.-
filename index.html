From device event to structured record in PROCEDA
PROCEDA captures the data that procedure-delivery devices already generate — but which no one has ever extracted and linked to patient outcomes at scale. Device logs, DICOM RT objects, HL7 streams, and edge sensors are parsed automatically at the moment of procedure close. No manual entry. No transcription error. No recall bias.
The problem is not that clinical data doesn't exist. It's that no one has built the infrastructure to capture it at the point where physics meets patient — and link it to outcomes. That is the only thing PROCEDA does, and it does it better than any system that has ever existed.

"The procedure-level delivery data linked to outcomes is something we cannot get from any EHR source. At 500 cases with 12-month follow-up, this would be relevant for our program."

— Senior Director, Oncology Clinical Science · Major pharma · [name withheld]
The Platform
Three-tier automated capture architecture
Tier 1 · Device APIs & DICOM
LOG / DICOM
Device log parse and DICOM RT object ingestion. Fires on procedure close or plan approval. Zero IT involvement for devices with existing DICOM output (SRS, HDR, robotic).
Tier 2 · Edge Hardware
EDGE / Serial
Raspberry Pi 5 + USB-serial adapter captures RS-232 streams at 1 Hz from RFA/MWA generators and OR environmental sensors. $110/device. Buffers offline. No hospital network required.
Tier 3 · HL7 / EHR
HL7 ADT/ORU
Standard HL7 feeds supplement device data with outcomes context: OR time, EBL, LOS, ICU admission, 30-day readmit. Existing hospital interfaces — no custom integration.
Human Input (Tier 4)
~8 Fields
Clinical judgment only: histology, margin status, applicator choice, conversion decision. Everything a machine cannot determine. Average 8 fields across all verticals.
Platform reuse is ~70% per new vertical. The ingestion pipeline, federated storage layer, and outcomes linkage logic are shared. Adding a new vertical requires only a device-specific parser and schema extension — not a rebuild.
All data is stored in a federated architecture: raw device data never leaves the institution's network. Only the structured extracted fields are transmitted to the central PROCEDA registry. HIPAA-compliant by design.
